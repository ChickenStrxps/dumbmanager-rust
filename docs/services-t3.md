# Native T3 service

DumbManager Rust keeps its own configuration, receipts, projects and DPAPI-protected session tokens in its own application data directory. Nothing is discovered from the original DumbManager or DumbAPI. The settings panel accepts an explicitly selected T3 distribution, CLI path, profile folder and loopback port. The user must open that T3 installation themselves, save its details, and explicitly connect. Pairing invokes only the selected CLI's `auth session issue` with orchestration read/operate scopes and a 30-day TTL, then probes the configured local endpoint before selecting it. Session material is never returned to the page. A failed probe keeps the prior selected connection. Regular, Knife and custom slots have independent configuration and credentials.

The service reads the local T3 shell and bounded thread projection through protocol version 2. It excludes subagents from choices and keeps exact thread IDs, including `mcp:` IDs. Published HTML previews are limited to completed `html_render` output references in that projection, fetched through a signed local attachment URL and returned as untrusted HTML for the existing sandbox. Chat and itch sends use the original `orchestration.dispatchCommand` WebSocket shape and queue after active work. The durable receipt records command and message IDs before dispatch, binds them to the request hash and the configured destination, and reuses them after an uncertain response. Changing the CLI/profile/port changes the target identity. Explicit user sends only; selecting a target or preparing a cook draft never dispatches.

Itch handoff freezes the original request and media mapping, saves every successful upload, stores the confirmed receipt and records it atomically in the itch. Retrying a confirmed receipt only completes any missing local record. Follow-up feedback is deduplicated by request key. Uploads use the signed local T3 endpoint without forwarding the bearer token. Image and original file uploads are supported; native video frameboard generation is unavailable, and a video in frameboard mode returns an explicit error. Upload or send failures do not establish delivery; retry with the same key. T3 must itself deduplicate command IDs for a lost acknowledgement to be safe.

Project registration stores only explicitly entered existing folders in `native-projects.json`, shared with Git and scout. No other project roots are scanned. The native settings supplement currently accepts paths as text; it requires a parent-provided native file/folder chooser for a graphical picker. Registration/removal does not modify the project folder.

Tests use temporary app state and loopback protocol fixtures. They cover wire headers, RPC commands, rejection of malformed IDs, filtered thread results, bounded preview references, signed uploads, stable identifiers after lost confirmation, and one-time local handoff recording. No real CLI session, T3 connection, external dispatch, live application UI, or video conversion was exercised by these tests. A fixture pass is not evidence of live T3 compatibility.
